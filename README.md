> 把每天的待辦丟進艾森豪四象限，做完一件就在對應顏色的方塊上填一格——一個讓「優先順序」變得看得見的工具。

## 它想解決什麼

那陣子我同時在跑履歷、面試準備、雅思、健身和社團的事。一開始我以為我需要一個更好的待辦清單，但誠實面對之後發現，**我的問題不是「忘記做事」**——忘記做事，隨便一個清單 App 就能解決。我真正卡住的是兩件事：

- **看不到自己推進了多少。** 清單只會愈列愈長，打勾的回饋很薄，一天結束我還是說不出今天到底有沒有前進。
- **分不清哪些事真正重要。** 清單把所有事排成平的一條，看起來每件都一樣重，它從來不會問我：這件事到底值不值得做。

所以這個工具解的不是記錄，是**判斷和回饋**。

## 怎麼用

1. 上方的週曆點一天（預設今天，也可以先排後天）
2. 打一件事，選一個象限，按加入
3. 做完打勾——對應象限的方塊會由下往上填色，盤面本身就是進度

資料存在你自己的瀏覽器裡，離線可用，不會上傳到任何地方。

## 四個象限

| 象限 | 意義 | 策略 | 顏色 |
|---|---|---|---|
| 立即完成 | 重要且緊急 | 立刻做，但儘量減少（避免長期高壓） | 🔴 紅 |
| 制定計劃 | 重要不緊急 | 投入最多時間（關鍵產出區） | 🔵 藍 |
| 委派 / 批次 | 緊急不重要 | 交給別人或集中處理 | 🟡 黃 |
| 刪除 / 限時 | 不重要不緊急 | 直接刪除或給它時間上限 | 🟢 綠 |

**顏色在這裡不是裝飾，是行動指令。** 而且失衡本身就是洞察：如果某天紅色填滿、藍色空空，一眼就知道「今天都在救火，沒做到關鍵產出」——畫面自己在提醒我調整。

## 幾個設計判斷

這些是做的過程中真正花時間想的地方，也是我覺得這個專案比「做出一個工具」更值得講的部分。

**不自己發明分類法。** 直接用艾森豪矩陣，因為它的每一格都對應一個行動策略（做／排／委派／刪），不只是標籤。

**跨日自動整理，不要求使用者記得按。** 第一版每天要手動按「新的一天」才會清空，但人一定會忘記，忘記就整盤失去意義。現在跨日會自動結算：完成的收起、沒做完的移到今天。**維護成本不該丟給使用者。**

**分類是會變的，工具就不能假設它不會變。** 事情會升級也會降級，所以任務可以隨時點一下或直接拖到別的象限。而且同一件事給兩種入口——拖曳給滑鼠，點選給手機（手機不支援拖曳，所以點選那條路必須留著）。

**行事曆只自動化輸入，不自動化判斷。** 可以一鍵把 Google 日曆當天的行程帶進來，但**全部拉進來讓使用者自己勾**，不靠顏色或關鍵字自動篩。工具負責省打字，不負責替人決定什麼重要。匯入的行程預設落在黃色而不是紅色，因為若讓會議自動灌滿紅色，「失衡就是洞察」這個訊號會永遠亮著，等於失效。

**年度格子刻意不用那四個顏色。** 紅藍黃綠在這個工具裡是「策略」的語彙，年度格子講的是「量」，混用會誤讀——尤其綠色在這裡是「刪除」，拿它當「做得好」意思完全相反。

**資料是你的。** 匯出／匯入用純文字複製貼上，不依賴檔案下載（下載在某些環境會被擋掉）。當初做它是為了換網址時搬家，後來換裝置、備份年度紀錄都靠它。

## 目前做到的

- 四象限分類，顏色直接對應行動策略
- 一週任一天都能規劃，不限於今天
- 點選或拖曳改分類，反映實際情況的變動
- 完成度換算成填色方塊，盤面即進度
- 跨日自動整理，完成的歸檔、沒做完的移到今天
- Google 日曆一鍵匯入當天行程（OAuth 串接）
- 年度回顧：一整年的格子圖，看得到連續性與空白期
- 純文字匯出／匯入，資料可搬到任何裝置
- 桌面浮動入口（macOS）：一個永遠置頂的小方塊，點一下開啟工具

## 技術

- 純 HTML / CSS / JavaScript，**單一檔案、零相依套件**
- 資料持久化：瀏覽器 `localStorage`
- Google Calendar API + Google Identity Services（OAuth 2.0，唯讀日曆）
- 響應式版面，支援深色 / 淺色主題
- 桌面外殼：Electron（只負責永遠置頂與開啟，不重複實作任何功能）

**架構上刻意做的一件事：資料、計算、畫面分開。** 任務清單是唯一的真相，填幾格是每次即時算出來的，不另外存。這樣改判斷標準只動邏輯、改外觀只動樣式，彼此不干擾——之後要加任務權重或接其他行事曆，都不用重寫。

行事曆的部分也切成三段：取得行程 → 轉成任務 → 匯入盤面。第一版的「取得」是手動貼上文字，接上 Google API 時只換掉第一段，後面兩段一行都沒改。

## 關於這個專案

我沒有寫程式的背景。這個工具是我自己定義問題、設計方案、再一步步做出來的——邊做邊學。

過程中最有價值的不是第一版，而是**自己用了幾天之後發現的那些問題**：入口做得太小自己都找不到、每天要手動重置、資料綁在網址上換個地方就不見、還有「今天／明天」根本不該被寫死。這些設計階段一個都沒想到。

對我來說它證明的一件事是：**看到問題，我有辦法把它變成能用的東西，而且會持續修到它真的好用。**
